# 查找器架构

仓库采用渐进式多模块结构。当前根项目仍然是可独立构建和发布的 TrialSpawnerFinder，外部配置、运行脚本和 JAR 名称保持不变。

## 当前模块

### finder-core

纯 Java 公共模块，不依赖 Fabric 或 Minecraft 服务端。目前只包含已经确认可复用的定义：

- `AreaShape`：圆形和方形范围判断。
- `BlockPoint`：二维方块坐标。
- `CircleCenter`：允许小数的候选圆心。
- `SearchBounds`：搜索矩形与世界边界裁剪。

该模块作为嵌套 JAR 打入 TrialSpawnerFinder 成品，发行时不需要额外携带文件。

### TrialSpawnerFinder 根项目

保留所有试炼密室专属逻辑：

- 1.21.1 结构放置候选枚举。
- 试炼密室聚类和分片扫描。
- 官方拼图结构生成及刷怪笼提取。
- 满足密室起点约束的精确圆心优化。
- 试炼专属配置、结果和 CSV 字段。

## 后续模块原则

新增紫水晶、海底神殿或女巫小屋查找器时，应创建独立子模块和独立发行包。只有至少两个查找器真正共享且语义一致的代码，才继续下沉到 `finder-core`。

不应把候选定位、精细生成或结果字段强行统一成一个万能接口：紫水晶依赖理论母岩坐标，试炼密室依赖拼图布局，低 Y 女巫小屋还依赖地表高度，它们的昂贵阶段并不相同。

建议开发顺序：

1. 保持 TrialSpawnerFinder 的固定种子测试结果不变。
2. 新建 GeodeFinder 子模块，实现纯算法筛选和可选真实验证。
3. 根据两个实际模块产生的重复代码，再抽取进度、分片和 Top N 等公共组件。
4. 最后加入普通结构聚类和地形高度筛选模块。
